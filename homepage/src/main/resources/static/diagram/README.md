# 업무 도식화 도구 (고객 설명용 / 개발자 설명용)

고객 요구사항과 개발자 고려사항을 입력하면 업무 흐름을 단계로 정리하고,
**고객 설명 모드**와 **개발자 설명 모드**의 흐름도(Mermaid)를 만들어 주는 단독 실행 웹 프로그램입니다.

## 실행 방법 (내부망 / 오프라인)

| 방법 | 설명 |
| --- | --- |
| 파일로 바로 열기 | `diagram` 폴더를 통째로 복사한 뒤 `index.html`을 브라우저(Chrome, Edge)로 엽니다. 서버가 필요 없습니다. |
| 홈페이지 서버로 열기 | Spring Boot 앱 실행 후 `http://<서버>:8080/diagram` 접속 (메인 메뉴 **Tools → 업무 도식화 도구**) |

- 외부 AI API, 인터넷, CDN을 사용하지 않습니다. 도식 엔진(`lib/mermaid.min.js`, Mermaid 11.4.1, MIT)이 폴더 안에 들어 있습니다.
- 페이지에 `Content-Security-Policy`(`connect-src 'none'`)를 걸어 두어 입력한 업무 정보가 외부로 전송될 수 없습니다.
- 작업 중인 내용은 브라우저 저장소(localStorage)에 자동 저장되고, **작업 파일 저장(JSON)**으로 내려받아 다시 열 수 있습니다.

## 사용 순서

1. **① 고객 요구사항**에 업무 흐름을 한 줄에 하나씩 입력합니다.
2. **② 개발자 고려사항**을 입력합니다. `[3] …` 또는 `3단계: …`로 시작하면 해당 단계에 연결되고, 그 외에는 내용이 비슷한 단계에 자동으로 연결됩니다.
3. 필요하면 **추가 정보**(업무 담당자, 사용자 역할, 관련 화면명, 시작/종료 조건, 업무 단계, 조건 및 예외사항, 변경 전/후 업무 방식)를 입력합니다.
4. **단계 자동 정리 → 도식 생성**을 누릅니다.
5. **단계 편집** 목록에서 유형, 담당, 문구, 조건 분기(예/아니오 처리, 이동할 단계)를 직접 고칩니다. 고친 내용은 바로 도식에 반영됩니다.
6. 오른쪽에서 **도식 유형**과 **설명 모드**(고객 / 개발자 / 두 모드 비교)를 고릅니다.
7. 결과를 SVG, PNG, Mermaid(.mmd)로 저장하거나, 코드를 복사하거나, 인쇄 / PDF로 저장합니다.

### 입력 작성 규칙 (규칙 기반 자동 정리)

| 입력 예 | 정리 결과 |
| --- | --- |
| `고객이 반품 신청 화면에서 사유를 입력한다.` | 업무 단계 (담당: 고객, 화면: 반품 신청 화면) |
| `필수 항목이 입력되었으면 신청을 접수한다.` | 조건(마름모) “필수 항목이 입력되었나요?” → 예: 신청을 접수 |
| `아니면 다시 입력하도록 안내한다.` (조건 다음 줄) | 같은 조건의 ‘아니오’ 처리. “종료”가 있으면 업무 종료로, “다시/돌아간다”가 있으면 앞 단계로 되돌아가도록 연결 |
| `# 반품 심사` | 업무 단위 구분. 업무 단위별로 흐름도를 나눔 |
| DB, 테이블, SQL, API, 연계 등이 들어간 문장 | 데이터·연계 단계. 고객 모드에서는 숨기거나 “시스템이 자동으로 처리”로 요약 |
| 조건 및 예외사항: `배송 후 7일 초과 → 반품 불가 안내` | 조건별 처리 결과 도식의 조건 / 결과 |

## 도식 유형

1. 업무 처리 흐름도: 시작, 업무 단계, 조건 판단, 종료
2. 역할별 업무 흐름도: 담당자(시스템 포함)별 영역으로 구분
3. 화면 이동 흐름도: 단계의 “관련 화면” 또는 관련 화면명 순서
4. 변경 전·후 비교도: 없어지는 단계와 새로 추가되는 단계를 표시
5. 조건별 처리 결과 도식: 조건마다 예 / 아니오 결과를 서로 다른 방향으로 연결

## 설명 모드의 차이

| 항목 | 고객 설명 모드 | 개발자 설명 모드 |
| --- | --- | --- |
| 기술 용어 (Java, DB, SQL, API, 테이블, 세션 등) | 숨기거나 쉬운 말로 바꿈 | 그대로 표시 |
| 데이터 조회·저장, 시스템 연계 단계 | 숨김 또는 “시스템이 자동으로 처리”로 요약 | 원통형·이중 사각형 등으로 구분해 표시 |
| 권한 확인 | “이용 권한이 있나요?” | 권한 조건 그대로 표시 |
| 오류 / 예외 | 고객이 이해할 수 있는 안내 문구로 바꿈 | 예외 처리 내용을 표시 |
| 노드 문구 | 짧게 줄바꿈(기본 한 줄 14자, 최대 3줄) | 화면명과 개발 상세(※)를 함께 표시 |
| 하단 문서 | “이런 경우에는 이렇게 안내됩니다” 표 | 개발 시 고려사항(데이터/권한/예외/연계/기타)과 단계 상세 표 |
| 흐름 분할 | 한 장 최대 단계 수(기본 10) 또는 업무 단위별 | 업무 단위별(최대 18단계) |

**두 모드 비교**를 고르면 두 도식을 나란히 보여 주고, 단계별로 표현이 어떻게 달라지는지 표로 보여 줍니다.

## 결과 수정

- 단계 편집 목록에서 수정하면 도식이 바로 다시 그려집니다.
- 각 도식의 **Mermaid 코드 보기·수정**에서 코드를 직접 고친 뒤 **수정한 코드로 다시 그리기**를 누르면 그 도식에 반영됩니다. **자동 생성으로 되돌리기**로 원래대로 돌아갈 수 있습니다.

## 파일 구성

```
diagram/
├── index.html          화면
├── css/diagram.css     화면·인쇄 스타일
├── js/model.js         단계 추출, 용어 변환, 오류 안내 문구 규칙
├── js/generator.js     도식 유형 / 모드별 Mermaid 코드 생성
├── js/export.js        SVG, PNG, .mmd, JSON 저장과 복사 (브라우저 안에서만 생성)
├── js/app.js           화면 동작, 예시 데이터
└── lib/                Mermaid 11.4.1 (오프라인 포함본), 라이선스
```

용어 변환이나 안내 문구 규칙은 `js/model.js`의 `TECH_TERMS`, `ERROR_RULES`에서 고칠 수 있습니다.
